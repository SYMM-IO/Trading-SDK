# InstantLayer hooks

React-query wrappers over `@symmio/trading-core`'s InstantLayer slice.

The page is split into two groups:

- **[Reads](#reads)** — `useDelegationExpiry`, `useIsDelegationActive`, `useInstantTradeRequiredSelectors`, `useInstantOpenFees`, `useInstantCloseFees`.
- **[Writes](#writes)** — `useGrantDelegation`.

Delegation reads are intentionally split into two hooks. `useDelegationExpiry` reads the raw `delegations` mapping value, and `useIsDelegationActive` reads the contract's computed active status.

## Reads

### `useDelegationExpiry`

Read the raw expiry timestamp for one account, delegate, and selector.

```tsx
import { useDelegationExpiry } from "@symmio/trading-react";

const expiryQuery = useDelegationExpiry({
  account,
  delegate,
  selector: "0x501e891f",
});

if (expiryQuery.data) {
  console.log(expiryQuery.data.toString());
}
```

#### Parameters

| Name       | Type      | Default        | Notes                             |
| ---------- | --------- | -------------- | --------------------------------- |
| `account`  | `Address` | required       | Account that owns the delegation. |
| `delegate` | `Address` | required       | Delegated signer being checked.   |
| `selector` | `Hex`     | required       | Function selector as `bytes4`.    |
| `chainId`  | `number?` | config default | Optional chain override.          |
| `query`    | `object?` | `undefined`    | TanStack Query overrides.         |
| `config`   | `Config?` | provider value | Optional config override.         |

#### Return type

`UseQueryResult<bigint, SymmioRequestError>`.

### `useIsDelegationActive`

Read whether the contract considers a delegation active.

```tsx
import { useIsDelegationActive } from "@symmio/trading-react";

const activeQuery = useIsDelegationActive({
  account,
  delegate,
  selector: "0x501e891f",
});

if (activeQuery.data === true) {
  console.log("Delegation is active");
}
```

#### Parameters

| Name       | Type      | Default        | Notes                             |
| ---------- | --------- | -------------- | --------------------------------- |
| `account`  | `Address` | required       | Account that owns the delegation. |
| `delegate` | `Address` | required       | Delegated signer being checked.   |
| `selector` | `Hex`     | required       | Function selector as `bytes4`.    |
| `chainId`  | `number?` | config default | Optional chain override.          |
| `query`    | `object?` | `undefined`    | TanStack Query overrides.         |
| `config`   | `Config?` | provider value | Optional config override.         |

#### Return type

`UseQueryResult<boolean, SymmioRequestError>`.

### Conditional UI

Because the read inputs are required, gate the hook-calling component until the UI has valid values.

```tsx
function DelegationPanel({ account, delegate, selector }: Props) {
  if (!account || !delegate || !selector) {
    return <p>Enter account, delegate, and selector.</p>;
  }

  return <DelegationReads account={account} delegate={delegate} selector={selector} />;
}

function DelegationReads({ account, delegate, selector }: Required<Props>) {
  const expiryQuery = useDelegationExpiry({ account, delegate, selector });
  const activeQuery = useIsDelegationActive({ account, delegate, selector });

  return (
    <>
      <p>Expiry: {expiryQuery.data?.toString()}</p>
      <p>Active: {String(activeQuery.data)}</p>
    </>
  );
}
```

### `useInstantTradeRequiredSelectors`

The session-key delegation selector set for the connected (or given) chain, resolved by its `contractsVersion`: the open leg is `sendQuote` on a perps-core v0.8.6 chain and the legacy `sendQuoteWithAffiliateAndData` on v0.8.5, while the close and add-margin selectors are the same on both. Synchronous — it reads config, not the chain.

```tsx
const selectors = useInstantTradeRequiredSelectors(); // or { chainId } to target another chain
const grant = useGrantDelegation();

grant.mutate({ account, delegatedSigner: sessionKey, selectors, expiryTimestamp });
```

Use it (instead of hardcoding `INSTANT_TRADE_REQUIRED_SELECTORS` / `LEGACY_INSTANT_TRADE_REQUIRED_SELECTORS`) in any flow that can point at more than one chain — a hardcoded set grants and checks the wrong open-leg selector on the other generation's chains. It returns the set in the order `grantDelegation` expects, and destructures cleanly for per-selector `useIsDelegationActive` probes: `const [addMarginSelector, openLegSelector, closeSelector] = useInstantTradeRequiredSelectors()`.

### `useInstantOpenFees`

Preview every fee a new instant-open quote pays **at open** — separated by leg plus the total — before the user submits. Read-only; nothing is signed. Wraps [`getInstantOpenFees`](../../core/solvers/instant-open#fee-preview--getinstantopenfees), which mirrors the exact resolution and math `prepareInstantOpenParams` charges, so the preview equals the real open for the same inputs.

The result is a `kind`-discriminated union of the **open-side legs only**. Both kinds carry `platformOpenFee`, `notional`, the sized `quantity`, and `totalFee`; an `"enigma"` (lowcap) result adds `openSolverFee`, `staticSolverFeeOpen`, and `expectedSettlementLoss`. `totalFee` sums the open legs and **includes the settlement provision by default** — pass `includeSettlementInTotalFee: false` to sum the fee legs only (the provision stays available as its own field); on majors it is just `platformOpenFee`. `staticSolverFeeOpen` is a **flat USD amount** from the solver's `/info` config ([`useSolverInfo`](../solvers#usesolverinfo)) — size-independent, `"0"` when the solver publishes none; the hook caches this read internally. Pass `solverInfo` to override it with already-resolved data. An unavailable `/info` keeps the existing zero-static-fee fallback. Close fees are **charged at close**, not funded at open — preview them in the close flow with [`useInstantCloseFees`](#useinstantclosefees), where the close notional and the holding-time solver rate are real (see [Fees at close](../solvers/instant-close#fees-at-close)).

With `fund: { mode: "full-balance", balance }` instead of `initialMargin` (lowcap only), the hook previews a [full-balance open](../../core/solvers/instant-open#full-balance-funding-lowcap): it runs the exact probe-and-rescale sizing the open runs, so the legs and `quantity` equal what the open will charge and submit. The extra inputs the sizing needs — the solver's locked-param percents (`useLockedParams`) and the market's quote constraints (from the same `useMarkets` read) — are prefetched through cached queries like every other input, so the query function stays pure math. In this mode `data.quantity` is the rescaled, lot-snapped size — feed it to TP/SL (see [`useInstantOpenWithTpSl`](../solvers/instant-open#useinstantopenwithtpsl)) instead of re-deriving it from a typed figure.

```tsx
const {
  data: fees,
  validationError,
  error,
  isReady,
} = useInstantOpenFees({
  subAccountAddress,
  market: { id: symbolId },
  positionType,
  initialMargin,
  leverage,
  // slippage — required on majors; omit on lowcap to auto-derive
});

// Display validationError ?? error first.
// isReady means fees describe the current inputs.
// fees?.totalFee — the open legs summed (settlement provision included)
if (fees?.kind === "enigma") {
  // fees.openSolverFee, fees.staticSolverFeeOpen, fees.expectedSettlementLoss
}
```

With `initialMargin` and `availableBalance`, the hook previews [automatic full-balance fallback](../../core/solvers/instant-open#automatic-fallback-from-typed-margin). Core compares required funding against the raw balance and returns `data.fundingMode` alongside the final `data.quantity`. Locked parameters and market constraints are prefetched for this mode too. Pass the same balance and estimate to preparation, fee preview, and submission; keep the typed input editable. Prefer the resolved mode and quantity over a local typed-margin cap check.

A typed `initialMargin` above `availableBalance` produces a synchronous `validationError`, including while offline, before requesting a price estimate or other prefills. Display `validationError ?? error`: `error` and `isError` describe the calculation query, while `validationError` describes invalid input. Invalid balance funding disables dependent queries; correcting the input clears `validationError` and resumes preparation. Explicitly disabled hooks and empty inputs stay idle without validation. Automatic fallback applies only when the typed amount fits but its required funding exceeds the balance.

`isReady` is true when validation passes, required inputs and the debounced estimate have settled, and the current calculation succeeds. Previous data may remain visible during recalculation; use it for the current order only when `isReady` is true. Pass `estimatedOpenPrice: null` for an estimate already attempted but unavailable, or omit it to let the hook request one. Both preparation and fees use the same unavailable-estimate fallback.

The query is disabled until a funding source exists — a non-empty `initialMargin` or a `fund` with a balance — and the funding value is part of the query key. Pass the raw input so validation stays immediate; estimate requests are debounced internally. Errors are normalized to `SymmioRequestError` (`SLIPPAGE_REQUIRED` on majors without a slippage, `INVALID_SLIPPAGE` on a malformed one, and in full-balance mode `QUOTE_CONSTRAINT_VIOLATED` when the sized quantity violates a published market constraint).

### `useInstantCloseFees`

Preview every fee closing a position pays **right now** — the platform close fee plus, on lowcap (Enigma), the holding-time solver close fee and the flat static close leg. Read-only; nothing is signed. The close-flow counterpart of [`useInstantOpenFees`](#useinstantopenfees), which deliberately previews only the open-side legs: the honest close cost exists only in the close flow, where the notional and the decaying solver rate are real. Wraps [`getInstantCloseFees`](../../core/solvers/instant-close#fee-preview--getinstantclosefees).

The hook **prefetches every input through its own cached queries and passes them in as prefills**, so the query function is pure math with zero network hops: market metadata and the close-fee schedule (`useMarkets`), the on-chain platform fee rates (`useFeeForUser`), and the solver's static fees ([`useSolverInfo`](../solvers#usesolverinfo), fail-soft) are slow-moving and cached for minutes; the mark price rides the shared price stream. Previous data is kept while inputs move, so a mark-price tick updates the numbers in place instead of flashing a loader.

The holding time is stamped each time the query function runs, so a **refetch re-prices the decaying solver close fee** as the position ages; pass `now` (unix seconds) for a deterministic preview. `openedAt` is typically the position's `createTimestamp`; omit it and the schedule prices the worst case (holding `0`, the peak rate).

```tsx
const { data: fees } = useInstantCloseFees({
  subAccountAddress: partyA,
  market: { id: symbolId },
  quantity: quantityToClose,
  openedAt: position.createTimestamp,
});
// fees?.totalFee; fees?.kind === "enigma" && fees.closeSolverFee
```

Parameters mirror the core action — `subAccountAddress`, `market: { id, … }` (optional pre-fetched metadata + schedule fields), the leveraged base-asset `quantity` to close, `openedAt?`, `now?`, the prefills `markPrice?` / `feeRates?` / `solverInfo?`, plus `chainId` / `solverId`, TanStack `query` overrides, and an optional `config`. The result is the same `kind`-discriminated union: both kinds carry `platformCloseFee`, `notional`, and `totalFee`; narrow on `kind === "enigma"` to reach `closeSolverFee`, `closeSolverFeeRate`, `holdingSeconds`, and `staticSolverFeeClose`. The query is disabled until a non-empty `quantity` exists; errors are normalized to `SymmioRequestError` (`INVALID_TRADE_PARAMETERS` on a non-positive quantity or unusable mark price).

## Writes

### `useGrantDelegation`

Submit an InstantLayer `grantDelegation` transaction.

```tsx
import { useGrantDelegation } from "@symmio/trading-react";

const { mutate, isPending, data, error } = useGrantDelegation();

<button
  disabled={isPending}
  onClick={() =>
    mutate({
      account: { addr: account, isPartyB: false },
      delegatedSigner: delegate,
      selectors: ["0x501e891f"],
      expiryTimestamp: 1_766_000_000n,
    })
  }
>
  Grant
</button>;
```

#### Options

```ts
interface UseGrantDelegationParameters {
  waitForReceipt?: boolean; // default true
  confirmations?: number; // default 1
}
```

#### Cache invalidation

On success, `useGrantDelegation` invalidates both read caches for the account and delegated signer:

- `getDelegationExpiryQueryKey`
- `getIsDelegationActiveQueryKey`

Mounted `useDelegationExpiry` and `useIsDelegationActive` hooks refetch independently.
