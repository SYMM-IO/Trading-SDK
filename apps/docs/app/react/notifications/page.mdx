# Notifications hooks

React hooks over the solver [Notifications](../../core/notifications) channel — a live WS stream plus a REST search over history.

**Read-only page.** `useNotifications` is a WebSocket subscription (still a "read" — no state mutation on-chain); `useSearchNotifications` is a REST-backed read.

<Callout type="info">
  The live stream (`useNotifications`) is protocol-agnostic: the underlying `watchNotifications` picks the resolved
  solver's notifications protocol (`enigma` on HyperEVM, `rasa` on Base) and the hook API is identical either way. Pass
  `solverId` to target a non-default solver. See [Solvers & Chains](../../core/concepts/solvers-and-chains) and the
  [Notifications protocol axis](../../core/notifications).
</Callout>

TP/SL has its own separate WebSocket over the same underlying `enigma` service (different `appName`). See [TP/SL](../tpsl).

## Import

```ts
import {
  useNotifications,
  useSearchNotifications,
  type Notification,
  type NotificationType,
} from "@symmio/trading-react";
```

## `useNotifications`

Subscribe to the live solver notifications WebSocket for one SubAccount. Returns the live socket status + delegates each parsed frame to your `onNotification` callback.

```tsx
const { status } = useNotifications({
  account: subAccount,
  enabled: true,
  onNotification: (notification) => {
    console.log(notification.type, notification.quoteId, notification.lastSeenAction);
  },
});
```

### Parameters

| Name             | Type                         | Default        | Notes                                                          |
| ---------------- | ---------------------------- | -------------- | -------------------------------------------------------------- |
| `account`        | `Address?`                   | `undefined`    | SubAccount. When unset, the subscription is idle.              |
| `enabled`        | `boolean?`                   | `true`         | Gate the subscription behind a flag (e.g. `live` toggle).      |
| `chainId`        | `number?`                    | config default | Optional chain override.                                       |
| `solverId`       | `SolverId?`                  | default solver | Target solver — selects the notifications endpoint + protocol. |
| `onNotification` | `(n: Notification) => void?` | `undefined`    | Fires per parsed frame.                                        |
| `onStatusChange` | `(s: SocketStatus) => void?` | `undefined`    | Connection status transitions.                                 |
| `onError`        | `(e: SymmError) => void?`    | `undefined`    | Transport / parse errors; does not stop the subscription.      |

### Return type

```ts
{
  status: SocketStatus;
  error: SymmioRequestError | null;
}
```

Consumers reading the raw frames typically pass them into `applyNotificationToQuotes` (via `useManagedQuotes`) or into their own local reducer.

### Connection pooling

Socket sharing follows the chain's protocol. On `enigma`, every subscriber on the same `(wsUrl, channel, account)` triple shares one pooled connection; on `rasa`, every account on the same endpoint multiplexes onto a single hub socket. See [Core `watchNotifications`](../../core/notifications/watch-notifications) and [Core WebSocket](../../core/concepts/websocket).

## `useSearchNotifications`

REST-backed paginated search over a solver's notification history — **one hook over both solver kinds**, dispatched by the resolved `solverId`:

- **enigma** → the standalone notification service (`POST /api/v1/search`), returning stored documents.
- **rasa** → the solver's own position-state endpoint (`POST /position-state/{start}/{size}`), returning position-state rows.

The result is a **per-kind union** — narrow on `data.kind` to read the variant's rows.

```ts
const page = useSearchNotifications({
  account: subAccount,
  quoteId: 1024,
  start: 0,
  size: 20,
});

if (page.data?.kind === "enigma") page.data.rows.map((document) => document.id);
if (page.data?.kind === "rasa") page.data.rows.map((row) => row.quote_id);
```

<Callout type="info">
  The **filters map per kind.** `tempQuoteId` and the free-form `filter` are enigma-only; `timestampGte` is rasa-only;
  `account` / `quoteId` / `start` / `size` map on both. Pass a literal `solverId` (or narrow on `data.kind`) to reach a
  variant's rows without casting.
</Callout>

### Parameters

| Name           | Type                        | Notes                                                                                                               |
| -------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `solverId`     | `SolverId?`                 | Target solver — selects the search endpoint + result variant. Defaults to chain's.                                  |
| `account`      | `Address?`                  | Filter: counterparty (SubAccount) address.                                                                          |
| `quoteId`      | `number?`                   | Filter: on-chain quote id.                                                                                          |
| `tempQuoteId`  | `number?`                   | Filter: pre-chain temporary quote id (negative). **Enigma only.**                                                   |
| `timestampGte` | `number?`                   | Filter: at/after this unix timestamp. **Rasa only.**                                                                |
| `start`        | `number?`                   | Zero-based offset of the first row. Defaults to `0`.                                                                |
| `size`         | `number?`                   | Max rows. Defaults to the endpoint default.                                                                         |
| `filter`       | `NotificationSearchFilter?` | Enigma-only advanced equality filter — top-level fields (`app_name`, …) or dotted `data.*` paths. Ignored for rasa. |
| `baseUrl`      | `string?`                   | Override the enigma notification-service base URL. Ignored for rasa.                                                |
| `chainId`      | `number?`                   | Optional chain override.                                                                                            |
| `query`        | `object?`                   | TanStack overrides.                                                                                                 |

### Return type

`UseQueryResult<NotificationSearchResult, SymmioRequestError>` — the per-kind union. Narrow on `data.kind`:

- `kind: "enigma"` → `{ total, count, rows }` where `rows` are raw `NotificationDocument`s (their `data` payload is the wire frame), not normalized `Notification`s.
- `kind: "rasa"` → `{ count, rows }` where `rows` are `PositionStateResponseSchema` records.
