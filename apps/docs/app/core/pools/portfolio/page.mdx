# Complete portfolio assembly

`getPoolPortfolio(config, parameters)` returns the complete user portfolio before presentation filters or pagination. Parameters are `GetPoolPortfolioParameters`: deployment, access token, optional catalog sort/range filters. It reuses listing and transaction actions; it creates no separate cache.

```ts
import { getPoolPortfolio, type Config } from "@symmio/trading-core";
export async function portfolio(config: Config, accessToken: string) {
  return getPoolPortfolio(config, { chainId: 42161, accessToken });
}
```

The action pages listed rows in groups of 100, loads four non-listed statuses as best-effort status lookups, and reads up to 1,000 deposit records in groups of 100. A non-listed catalog row cannot create a holding: only a deposit-backed entry is included. Listed order is retained. Apply chain/search/status presentation filters after this assembly.

`assemblePoolPortfolio(markets, nonListed, deposits)` performs the same assembly over already available inputs. Its generic `PoolPortfolioEntry<M, D>` preserves the source `market` or `deposit`, the resolved `marketStatus`, and optional `history`. `PoolPortfolioMarket` and `PoolPortfolioDeposit` specify minimal identities/amounts; extra consumer fields pass through. `PoolPortfolioTransaction` adds catalog identity to a normalized user transaction.

`sumPoolDepositHistory(deposits)` returns `PoolDepositHistory` with pending/transferred/refund/rejected/success bigints at 18 decimals. Legacy deposit spellings are accepted; `decimals` describes the input amount's scale, defaulting to 18. EVM identities are folded, Solana identities retain case.

See [portfolio totals and deposit calculations](/core/pools/calculations). Missing profit requests must remain unknown in consumer UI; portfolio assembly cannot infer a current balance from cumulative deposits.
