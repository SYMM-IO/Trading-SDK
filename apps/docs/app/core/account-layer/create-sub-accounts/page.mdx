# createSubAccounts

Create one or more subaccounts under an affiliate. A direct wallet transaction creates them for that wallet;
a gasless operation creates them for the billing account's owner, including when a delegated session key signs.

```ts
import { createSubAccounts, encodeSubAccountHookMetadata, SubAccountIsolationType } from "@symmio/trading-core";

const hash = await createSubAccounts(config, {
  affiliate: "0xaff...",
  accountsData: [
    {
      name: "Main",
      metadata: encodeSubAccountHookMetadata({ partyBToBind: solverAddress }),
      symmioCore: "0xcore...",
      isolationType: SubAccountIsolationType.MARKET,
      singleVAMode: true,
    },
  ],
});
```

The created addresses are deterministic and returned by the contract call, but they are only readable once the
transaction is mined — take them from the `SubAccountCreated` events on the receipt, or refetch
[`getUserSubAccounts`](/core/account-layer/get-user-sub-accounts).

## Hook metadata

The affiliate's `onAccountCreation` hook receives each entry's `metadata` unchanged and decides its encoding. A blob the
hook rejects reverts the whole call with `HookFailed`. For the chain's default affiliate, build the blob with
[`encodeSubAccountHookMetadata`](/core/account-layer/encode-sub-account-hook-metadata), passing the chain's solver as
`partyBToBind`. Its referral code is global and single-use, so never reuse a fixed one. An affiliate with its own hook
needs the blob that hook decodes.

## Relaying it without gas

`createSubAccounts` relays like any other [relayable write](/core/gasless/relayable-writes). The relayer scopes the
AccountLayer call to the billing account's owner. That owner receives the new accounts even when a delegated
session key signs the operation.

```ts
const hash = await createSubAccounts(config, {
  affiliate: "0xaff...",
  accountsData,
  gasless: { enabled: true, account: existingSubAccount },
});
```

<Callout type="warning">
  This is the one relayable write that **requires `gasless.account`**. Every relayed operation is signed under an
  account the InstantLayer can resolve on chain, and the subaccounts being created do not exist yet — so an existing
  owned subaccount has to sign, and it pays the operational fee. Without it the call throws
  `GASLESS_ACCOUNT_UNRESOLVED`. A wallet with no subaccount at all cannot bootstrap this way; use
  [`settleGaslessDepositNewAccount`](/core/gasless/settle-gasless-deposit-new-account), which creates the first account
  as part of the deposit.
</Callout>

## Parameters

<Properties>
  <Property name="affiliate" type="Address" required>
    Affiliate that custodies the new subaccounts. Must be `ACTIVE` on chain, and each entry's `symmioCore` must be
    whitelisted and registered for it.
  </Property>
  <Property name="accountsData" type="readonly SubAccountCreationData[]" required>
    One entry per subaccount to create — `name`, `metadata`, `symmioCore`,
    [`isolationType`](/core/account-layer/sub-account-isolation-type) and `singleVAMode`. The created addresses come
    back in this same order.
  </Property>
  <Property name="chainId" type="number" optional>
    Optional chain override.
  </Property>
  <Property name="simulateBeforeWrite" type="boolean" optional>
    Dry-run wallet execution via `simulateContract` first, including wallet fallback (defaults to the config's setting,
    itself `true` by default).
  </Property>
  <Property name="gasless" type="boolean | GaslessWriteOptions" optional>
    Relay this write through the [gasless execution mode](/core/gasless/relayable-writes) instead of the wallet.
    `gasless.account` is required — see the callout above.
  </Property>
</Properties>

## Returns

<Returns type="Hash">The broadcast tx hash. The caller waits for the receipt.</Returns>

## Recovering an interrupted creation

A relayed creation can end without a clear answer — a lost response, a closed page, a timed-out wait. Give each user action its own `gasless.idempotencyKey`, save it before calling, and call again under the same key: the service accepts the key at most once, so the account is never created twice.

```ts
import { createSubAccounts, generateGaslessIdempotencyKey } from "@symmio/trading-core";

const key = generateGaslessIdempotencyKey();
await pendingActions.save({ key, affiliate, accountsData, payer });

const hash = await createSubAccounts(config, {
  affiliate,
  accountsData,
  gasless: { account: payer, idempotencyKey: key },
});
```

A key makes the call strictly gasless: it never falls back to the wallet on its own. [Recovering gasless writes](/core/gasless/recovering-writes) covers the full lifecycle — what to save, how to read each outcome, and how to reconcile one that stays unknown.
