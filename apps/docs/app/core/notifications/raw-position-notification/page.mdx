# RawPositionNotification

The raw position-state notification frame as it arrives on the wire (snake_case), mirroring the hedger/solver payload. Consumers normally receive the normalized [`Notification`](/core/notifications/notification); the raw frame is retained on it as `raw`.

The endpoint omits fields that do not apply to a given frame (for example an `InstantRFQ` report carries no `id`), so almost every field is optional; [`normalizeNotification`](/core/notifications/normalize-notification) fills sensible defaults.

  </Property>

  </Property>

  </Property>
  <Property name="action_status" type="string | null" optional>
    `success` | `failed` | `seen`.
  </Property>
  <Property name="failure_type" type="string | null" optional />

  <Property name="error_code" type="number | null" optional />

  </Property>
  <Property name="version" type="number" optional />
  <Property name="avg_price_open" type="string" optional />
  <Property name="avg_price_close" type="string" optional />
</Properties>

## DefilyticsNotificationEnvelope

The `defilytics` endpoint nests the notification under `data`, with the SubAccount address hoisted to the top level. [`parseNotificationFrame`](/core/notifications/parse-notification-frame) unwraps it back into a `RawPositionNotification`.

<Properties>
  <Property name="data" type="RawPositionNotification">
    The nested notification frame.
  </Property>
  <Property name="address" type="string">
    The SubAccount address, hoisted to the envelope root.
  </Property>
</Properties>
