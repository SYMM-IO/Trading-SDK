# RawPositionNotification

The raw position-state notification frame as it arrives on the wire (snake_case), mirroring the hedger/solver payload — **one variant per notifications protocol**, unioned:

```ts
type RawPositionNotification = RawEnigmaPositionNotification | RawRasaPositionNotification;
```

Consumers normally receive the normalized [`Notification`](/core/notifications/notification); the wire-faithful frame is retained on it as `raw`. The endpoints omit fields that do not apply to a given frame (for example an `InstantRFQ` report carries no `id`), so almost every field is optional; [`normalizeNotification`](/core/notifications/normalize-notification) fills sensible defaults and reconciles the per-wire value quirks.

## Shared fields (both variants)

Fields both wires return. Amount/price fields are typed to the widest wire form (`number | string | null`) — rasa sends a numeric `0` for "no value", enigma only ever a decimal string. Only fields **exclusive** to one wire live on the variants.

<Properties>
  <Property name="id" type="string" optional />
  <Property name="quote_id" type="number" optional>
    On-chain quote id — `0` (enigma) or the negative temp id (rasa) while the order is still off-chain.
  </Property>
  <Property name="temp_quote_id" type="number" optional>
    Negative placeholder id assigned before the on-chain quote id exists.
  </Property>
  <Property name="create_time" type="number" optional />
  <Property name="modify_time" type="number" optional />
  <Property name="counterparty_address" type="string" optional />
  <Property name="address" type="string" optional>
    SubAccount address the notification belongs to. On the enigma wire it is hoisted from the envelope; rasa frames do
    not carry it — the watcher stamps it from its own subscription.
  </Property>
  <Property name="filled_amount_open" type="number | string | null" optional>
    Filled base amount on the open leg. Decimal string when present (enigma always; rasa on a `report`); numeric `0` on
    a rasa `alert` duplicate; absent/`null` otherwise. Same for the three fields below.
  </Property>
  <Property name="filled_amount_close" type="number | string | null" optional />
  <Property name="avg_price_open" type="number | string | null" optional />
  <Property name="avg_price_close" type="number | string | null" optional />
  <Property name="last_seen_action" type="string | null" optional>
    Last solver action seen for this quote (e.g. `SendQuoteTransaction`).
  </Property>
  <Property name="action_status" type="string | null" optional>
    `success` | `failed` | `seen`.
  </Property>
  <Property name="failure_type" type="string | null" optional />
  <Property name="error_code" type="number | null" optional />
  <Property name="state_type" type="string | null" optional>
    `report` | `alert`.
  </Property>
</Properties>

## RawEnigmaPositionNotification

The `enigma` (channel-scoped) wire, after the envelope unwrap. Adds the fields only this wire carries; on this wire the shared amount/price fields are always decimal strings (or `null`/absent), never numbers.

<Properties>
  <Property name="va_address" type="string" optional>
    Solver-assigned Virtual Account address (lowcap), when present.
  </Property>
  <Property name="failure_message" type="string | null" optional />
  <Property name="version" type="number" optional />
</Properties>

## RawRasaPositionNotification

The `rasa` position-state wire, bare (no envelope), kept exactly as sent. The shared amount/price fields are the numeric `0` when the frame carries no value (an `alert` duplicate) and a decimal string when it does (a `report`); `normalizeNotification` reconciles them.

<Properties>
  <Property name="order_type" type="number" optional>
    Order type discriminant the rasa wire attaches (e.g. `1`).
  </Property>
</Properties>

## EnigmaNotificationEnvelope

The `enigma` endpoint nests the notification under `data`, with the SubAccount address hoisted to the top level. [`parseNotificationFrame`](/core/notifications/parse-notification-frame) unwraps it back into a `RawEnigmaPositionNotification`.

<Properties>
  <Property name="data" type="RawEnigmaPositionNotification">
    The nested notification frame.
  </Property>
  <Property name="address" type="string">
    The SubAccount address, hoisted to the envelope root.
  </Property>
</Properties>
