# getCandlesQueryOptions

Build TanStack Query options for a [`CandleSource`](/core/candles/candle-source-type)'s historical bars.

Unlike the chain-scoped factories elsewhere in the SDK, this takes a **source** rather than a `Config`: which venue to chart is the consumer's choice, not a property of the SYMMIO deployment. The source's `id` is folded into the query key so switching venues does not read another venue's cached bars.

```ts
import { createBinanceCandleSource, getCandlesQueryOptions } from "@symmio/trading-core";

const source = createBinanceCandleSource();

const options = getCandlesQueryOptions(source, {
  marketName: "BTCUSDT",
  resolution: "1m",
  from: rangeStart,
  to: rangeEnd,
});

// queryClient.fetchQuery(options) / useQuery(options)
```

## Parameters

<Properties>
  <Property name="marketName" type="string">
    Market name as SYMMIO names it (e.g. `"BTCUSDT"`).
  </Property>
  <Property name="resolution" type="CandleResolution">
    Bar size to fetch. Must be listed in the source's `supportedResolutions`. See
    [Resolutions](/core/candles/resolutions).
  </Property>
  <Property name="from" type="number">
    Range start, unix **milliseconds**, inclusive.
  </Property>
  <Property name="to" type="number">
    Range end, unix **milliseconds**, exclusive.
  </Property>
  <Property name="limit" type="number" optional>
    Maximum bars to return. A source pages internally to satisfy this, so it may exceed the venue's own per-request cap.
  </Property>
  <Property name="query" type="QueryParameter" optional>
    TanStack overrides (`staleTime`, `enabled`, …).
  </Property>
</Properties>

## Returns

<Returns type="GetCandlesQueryOptions">
  Options to pass to `useQuery` / `queryClient.fetchQuery`. The resolved data is `GetCandlesData` — `candles` in
  ascending time order, de-duplicated and clipped to the requested range, plus a `noMoreData` flag.
</Returns>

`noMoreData` is `true` when the source confirms there is no earlier history to page into. A chart paging backwards should stop when it sees this. The result can still contain candles, including the instrument's earliest available bar.

<Callout type="warning">
  `from`/`to` are part of the query key. Passing a live `Date.now()` mints a new cache entry on every call — derive the
  range from state that only changes when the user actually pans or changes resolution.
</Callout>

For providers without history-boundary metadata, `noMoreData: false` means exhaustion is unknown. Empty windows can be gaps. See the [lowcap source compatibility note](/core/candles/lowcap-source#knowing-when-older-history-ends). Use `staleTime: 0` for mutable history and refetch on the stream's `onReset`; do not mark recent OHLCV immutable.

## Query key

`getCandlesQueryKey` builds the key on its own — its options take a `sourceId` in place of the source object:

```ts
import { getCandlesQueryKey } from "@symmio/trading-core";

const key = getCandlesQueryKey({
  sourceId: source.id, // e.g. "binance:usd-m-futures"
  marketName: "BTCUSDT",
  resolution: "1m",
  from,
  to,
});
// → ["getCandles", { sourceId, marketName, resolution, from, to }]
```

`signal` is excluded from the key. The query function forwards TanStack's abort signal to the source, including through `useCandles`, so obsolete pages can be cancelled. Direct `queryFn()` calls remain supported without a signal.

## getCandleHistoryQueryOptions

Build an incremental history query for any `CandleSource`. This factory is framework-neutral: use it with TanStack’s `InfiniteQueryObserver` or a framework infinite-query hook. React consumers can use [`useCandleHistory`](/react/candles#usecandlehistory).

```ts
import { getCandleHistoryQueryOptions } from "@symmio/trading-core";

const options = getCandleHistoryQueryOptions(source, {
  marketName,
  resolution: "1h",
  from: rangeStart,
  to: rangeEnd,
  followLatest: true,
  query: { staleTime: 0, retry: false },
});
// useInfiniteQuery(options) / new InfiniteQueryObserver(queryClient, options)
```

```ts
function getCandleHistoryQueryOptions(
  source: CandleSource,
  options: GetCandleHistoryOptions,
): GetCandleHistoryQueryOptions;

function getCandleHistoryQueryKey(parameters: GetCandleHistoryQueryKeyParameters): GetCandleHistoryQueryKey;
```

The required inputs are `marketName`, `resolution`, `from`, and `to`. Bounds are integer milliseconds and must satisfy `from < to`. Optional `followLatest` defaults to `false`; when enabled, only the newest window’s end advances through the current time when fetched. `query` accepts TanStack observer overrides except the SDK-owned key, function, selection, page cursors, and page eviction settings.

Calling `fetchNextPage` requests `[oldestRequestedFrom - (to - from), oldestRequestedFrom)`. It does not download loaded windows again. Cursors come from requested dates, including empty windows, rather than candle counts or the first returned candle. The source owns bucket alignment, internal HTTP limits, and flat-candle filtering. No consumer bar limit is passed, so a page cannot silently discard part of its requested range.

Guard calls with `!isFetching && hasNextPage` and pass `{ cancelRefetch: false }` to deduplicate concurrent page requests. A normal refetch revalidates every retained window, including removals and corrections, following [TanStack's infinite-query behavior](https://tanstack.com/query/latest/docs/framework/react/guides/infinite-queries#what-happens-when-an-infinite-query-needs-to-be-refetched). For a source correction with known bounds, use [`refreshCandleHistory`](#refreshcandlehistory) to fetch only corrected intervals. Do not treat retained data as final or disable correction-triggered refreshes.

The selector retains TanStack’s `pages` and `pageParams` and adds ascending, duplicate-free `candles` and `noMoreData` from the oldest requested window. It preserves the source’s candles, including any first-candle exception per separately requested window. Query identity includes the source id, market, resolution, initial range, and follow policy; keep the initial range stable during paging.

| Type                                 | Shape / purpose                                                                         |
| ------------------------------------ | --------------------------------------------------------------------------------------- |
| `CandleHistoryRange`                 | `{ from: number; to: number }` in milliseconds.                                         |
| `CandleHistoryPage`                  | A requested range plus `{ candles, noMoreData }`.                                       |
| `CandleHistoryData`                  | `{ pages, pageParams, candles, noMoreData }`; pages newest first, candles oldest first. |
| `GetCandleHistoryParameters`         | Market, resolution, initial range, and optional `followLatest`.                         |
| `GetCandleHistoryOptions`            | Parameters plus `query` overrides.                                                      |
| `GetCandleHistoryQueryKeyParameters` | Parameters plus `sourceId`.                                                             |
| `GetCandleHistoryQueryKey`           | `["getCandleHistory", { sourceId, marketName, resolution, from, to, followLatest }]`.   |
| `GetCandleHistoryQueryOptions`       | Infinite-query observer options returned by the factory.                                |

The returned options include `fetchRange(range, signal): Promise<CandleHistoryPage>` for exact-range reads. It uses the same source, market, resolution, and cancellation rules as `queryFn`, but never extends the range for `followLatest`. `refreshCandleHistory` uses it for corrections. If you wrap errors for a framework, wrap both `queryFn` and `fetchRange` consistently; the React hook does this for you.

## refreshCandleHistory

Revalidate an incremental history query using the same `QueryClient` and options that own its retained pages. Pass the optional range from `watchCandles.onReset` to fetch only corrected intervals. Omit it for a full refresh. React consumers use [`history.refresh(range)`](/react/candles#usecandlehistory).

```ts
function refreshCandleHistory(queryClient: QueryClient, parameters: RefreshCandleHistoryParameters): Promise<void>;

interface RefreshCandleHistoryParameters {
  queryOptions: GetCandleHistoryQueryOptions;
  range?: CandleHistoryRange;
  signal?: AbortSignal;
}
```

| Parameter      | Meaning                                                                                                    |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| `queryClient`  | TanStack client owning this history query.                                                                 |
| `queryOptions` | The original `getCandleHistoryQueryOptions` result, including any query-function error wrapper.            |
| `range?`       | Corrected candle starts, in integer milliseconds: inclusive `from`, exclusive `to`. Requires `from < to`.  |
| `signal?`      | Cancels a scheduled refresh before it starts. An existing shared query owns cancellation of its transport. |

A bounded refresh waits for active or offline-paused paging to finish, then fetches the corrected intervals within retained windows. It replaces candles in those intervals, including removals, and preserves the others. The original paging boundaries stay intact; exhaustion is updated only when the beginning of a page is fetched again. Flat-candle filtering is evaluated by the source for each requested interval. A correction outside a fixed retained range makes no request. With `followLatest: true`, any missing tail is also fetched through the current time. This read overlaps one interval before the previous cutoff so a candle that was still forming is revalidated, even if it was previously absent. Monthly resolutions use a 31-day overlap; each source retains ownership of bucket alignment. Adjacent or overlapping intervals share a request; separated corrections and tails are fetched independently, so a small correction does not redownload an entire growing page. If no history is retained, the initial window is fetched.

A full refresh cancels active work for this query and revalidates all retained windows. Both modes expose loading and errors through the original query; existing data remains available during refresh and after a failure. The promise rejects on a request failure or cancellation; invalid bounds throw `INVALID_CANDLE_RANGE`. A source can split each window into multiple HTTP requests.

```ts
import { getCandleHistoryQueryOptions, refreshCandleHistory } from "@symmio/trading-core";

const queryOptions = getCandleHistoryQueryOptions(source, {
  marketName,
  resolution: "1h",
  from: rangeStart,
  to: rangeEnd,
  followLatest: true,
});

await queryClient.fetchInfiniteQuery(queryOptions);
await refreshCandleHistory(queryClient, {
  queryOptions,
  range: { from: correctedCandleStart, to: correctedCandleStart + 3_600_000 },
});
```

Observer refetch policies still apply independently. For a chart that refreshes through source resets and an explicit Refresh control, set `query.refetchOnWindowFocus: false` to avoid a full refetch on every return to the tab. This does not make history immutable or disable explicit corrections.
