# grantDelegations

Grant several delegated signers of one account in a single call — `InstantLayer.grantDelegations`. Each entry keeps
its own selectors and expiry.

```ts
import { grantDelegations } from "@symmio/trading-core";

const hash = await grantDelegations(config, {
  account: { addr: subAccount, isPartyB: false },
  delegations: [
    { delegatedSigner: sessionKey, selectors: sessionKeySelectors, expiryTimestamp },
    { delegatedSigner: tpslExecutor, selectors: tradingSelectors, expiryTimestamp },
  ],
  gasless: true,
});
```

Reach for it when one setup step authorizes more than one signer, for example a session key for trading and a TP/SL
executor for conditional orders. Relayed, the whole grant is **one owner signature** instead of one per delegate; from
the wallet, it is one transaction. To grant a single signer, [`grantDelegation`](/core/instant-layer/grant-delegation)
is enough.

Like `grantDelegation`, a grant clears any pending revocation for the selectors it covers.

<Callout type="warning">
  The InstantLayer must have `grantDelegations`, which perps-core v0.8.6 added on 2026-09-04. A deployment older than
  that reverts with no matching function. The SDK cannot tell from config, so gate the UI on your knowledge of the
  deployment.
</Callout>

## Parameters

<Properties>
  <Property name="account" type="InstantLayerAccount" typeHref="/core/instant-layer/instant-layer-account" required>
    The PartyA account that grants every delegation. The connected wallet must own it. The contract applies all entries
    to this one account, so a PartyB account is rejected before any prompt with `GRANT_DELEGATIONS_PARTYB_UNSUPPORTED`.
  </Property>
  <Property name="delegations" type="readonly GrantDelegationsEntry[]" required>
    One entry per delegate: `{ delegatedSigner, selectors, expiryTimestamp }`. Must not be empty; an empty list is
    rejected before any prompt with `GRANT_DELEGATIONS_EMPTY`.
  </Property>
  <Property name="chainId" type="number" optional>
    Optional chain override.
  </Property>
  <Property name="simulateBeforeWrite" type="boolean" optional>
    Dry-run via `simulateContract` first (defaults to the config's setting, itself `true` by default). Ignored on the
    relayed path, where the relayer simulates its own bundle.
  </Property>
  <Property name="gasless" type="boolean | GaslessWriteOptions" optional>
    Relay the grant instead of sending a transaction. Omitted, the chain's `gasless.execution.mode` decides. See
    [relayable writes](/core/gasless/relayable-writes).
  </Property>
</Properties>

## Returns

<Returns type="Hash">
  The submitted transaction hash. A relayed grant returns the relayer's broadcast hash, which behaves exactly like a
  wallet-submitted one. Dry-run without sending via `simulateGrantDelegations(config, params)`.
</Returns>

## In a gasless batch

`grantDelegations` is a relayable write, so a [gasless batch](/core/gasless/relay-gasless-batch) can carry it by name.
A call later in the same batch can then be signed by one of the delegates it grants: the batch executes in order, so
the grant lands first. That is the one-signature setup — the owner signs the grant, and the new session key silently
signs the rest. See [mixing signers](/core/gasless/relay-gasless-batch#mixing-signers).
