# classifyQuoteNotificationAction

Classify a notification's `lastSeenAction` into the quote flow it belongs to. Consumers use the result to scope cache invalidation to the reads a notification can actually affect — an open-anchor event never changes the pending-instant-close feed, and vice versa.

Open-side actions (anchoring an open, or the `InstantRFQ` price fill) classify as `"open"`; close-request/fill actions classify as `"close"`; anything else (including failures and unknown actions) is `"other"`.

```ts
import { classifyQuoteNotificationAction } from "@symmio/trading-core";

if (classifyQuoteNotificationAction(n.lastSeenAction) === "close") invalidateCloses();
```

## Parameters

<Properties>
  <Property name="action" type="string | null | undefined" required>
    The notification's `lastSeenAction` (may be `null`/absent).
  </Property>
</Properties>

## Returns

<Returns type="QuoteNotificationActionKind" typeHref="/core/quotes/quote-notification-action-kind">
  The quote flow the action belongs to — `"open"`, `"close"`, or `"other"`.
</Returns>

## `isOpenAnchorAction`

Boolean helper that narrows the same `lastSeenAction` to just the on-chain **anchor** actions (`SendQuoteTransaction` / `SendQuote` / `FillLimitOrderOpen`) — the _second_ notification of a send flow, where the temp id gains a real on-chain quote id. Excludes the earlier off-chain `InstantRFQ` price fill (which `classifyQuoteNotificationAction` still calls `"open"`). Use it to refetch reads that only change once the quote exists on-chain — e.g. the pending / limit-order list.

```ts
import { isOpenAnchorAction, NotificationType } from "@symmio/trading-core";

if (n.type === NotificationType.SUCCESS && isOpenAnchorAction(n.lastSeenAction)) refetchPending();
```
