# ABI fragments

Raw viem-style `Abi` arrays for the SYMMIO contracts, for consumers who call viem directly (bypassing the SDK's typed actions). Use these as an **escape hatch** — the typed actions are recommended for everything the SDK already covers.

## Import

```ts
import { accountLayerAbi, instantLayerAbi, symmioAbi } from "@symmio/trading-core";
```

Each is a `readonly Abi` array exported straight from the versioned `src/symmio-contracts/abi/v0.8.6/` files.

The shipped ABIs target `v0.8.6`, sourced from [`perps-core` at revision `3e25e6e`](https://github.com/SYMM-IO/perps-core/tree/3e25e6e2130702e92668aeb2dec68395ac25129f/abis). `symmioAbi` and `accountLayerAbi` contain the complete source arrays. `instantLayerAbi` contains the three delegation methods used by the SDK: `delegations`, `grantDelegation`, and `isDelegationActive`; these entries also match that revision.

## Compatibility changes

Direct ABI consumers should account for these changes from the previous SDK snapshot:

| Contract     | Change                                                                                                                                                 |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| SYMMIO       | `startRestatement` now requires `symbolId` and `expectedLiquidationStartNonce`. Use this two-argument signature in place of the old one-argument call. |
| SYMMIO       | `RestatementPreparationCompleted` adds a `phase` (`uint8`) event argument.                                                                             |
| SYMMIO       | `getSymbolAdjustment` adds `pendingQuoteIdCutoff` and `fundingSettlementRequired` to its returned tuple.                                               |
| SYMMIO       | Use `pausePartyBOpenPositionsFor(partyB)` or `unpausePartyBOpenPositionsFor(partyB)` in place of `setPartyBOpenPositionsPaused(partyB, status)`.       |
| AccountLayer | The ABI includes timelock setup, approval, scheduling, execution, and read methods, plus their events and errors.                                      |

For contract behavior, see the matching [symbol-adjustment documentation](https://github.com/SYMM-IO/perps-core/blob/3e25e6e2130702e92668aeb2dec68395ac25129f/docs/v0.8.6/pages/symbol-adjustment.html), [admin-role changes](https://github.com/SYMM-IO/perps-core/blob/3e25e6e2130702e92668aeb2dec68395ac25129f/docs/v0.8.6/pages/narrower-admin-roles.html), and [AccountLayer timelocks](https://github.com/SYMM-IO/perps-core/blob/3e25e6e2130702e92668aeb2dec68395ac25129f/docs/v0.8.6/pages/accountlayer-timelock.html). A raw ABI entry does not imply an SDK action or React hook exists for that method.

## Usage — viem `readContract`

```ts
import { createPublicClient, http } from "viem";
import { arbitrum } from "viem/chains";
import { accountLayerAbi } from "@symmio/trading-core";

const client = createPublicClient({ chain: arbitrum, transport: http() });

const result = await client.readContract({
  address: "0x…",
  abi: accountLayerAbi,
  functionName: "getSubAccountsCountOfUser",
  args: [user],
});
```

## Usage — viem `writeContract`

```ts
import { walletClient } from "./client";
import { symmioAbi } from "@symmio/trading-core";

const hash = await walletClient.writeContract({
  address: "0x…",
  abi: symmioAbi,
  functionName: "allocate",
  args: [amount],
});
```

Pair with `Config.getChainConfig(chainId).addresses` (see [Addresses](../addresses)) for the deployment-specific address.

## When to reach for the ABI vs typed actions

Prefer the typed action when one exists:

- Typed actions run through `Config.getClient` / `getWalletClient`, so chain switching and wallet routing already work.
- They wrap responses in typed shapes (`Quote`, `Market`, `LockedValues`) with 18-decimal-wei `bigint`.
- They surface SDK errors (`SymmError` / `SymmApiError`) instead of raw viem errors when the failure is config-level.

Reach for the ABI directly when:

- The function isn't wrapped by the SDK yet.
- You want raw viem semantics (e.g. `multicall` batches, custom overrides).
- You're building diagnostics that need untouched ABI-level output.
